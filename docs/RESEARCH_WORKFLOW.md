# Bounded development workflow

D008 provides local state/retrieval libraries and a one-shot development broker. The broker can dispatch bounded model roles, retrieve authorized failure metadata and run a newly registered local calculation. Synthetic integration is verified; actual-model historical acceptance is pending. Protected storage, unattended research and operational recovery remain separate stages in [the accepted contract](D008_POLICY.md).

## Broker entrypoint and evidence

`quanto run-research --request PATH` runs one explicit workflow using the private project store. This is a paid operational-model command, not the Fable/Opus council route. It accepts exactly `run_key`, `suite_sha256`, `failure_ids`, `models` and `evidence_kind`. The supervisor supplies a new bounded run key, the digest of an already registered D007 suite, up to16 exact failure identities (`source` plus `id`), all seven role-to-model mappings and `historical_market_data`. The CLI does not accept arbitrary shell commands, model tools, endpoint overrides, SQL, acquisition requests or orders. Injected transports are library/test-only and must declare `synthetic_fixture`.

The seven ordered stages are director, hypothesis, engineer, data critic, statistical critic, quality and scope. The default mapping uses Haiku for five stages and Opus for both critics. Each call records the actual responding model; a test response using a real model name remains synthetic evidence. The implementation has a USD2.625 whole-run planning ceiling for that default mapping, per-role limits, a USD4 research-purpose daily allowance and the existing shared USD20 America/Los_Angeles daily ceiling. Planning headroom is not a reservation; every dispatch independently and atomically enforces the current allowances. Uncertain outcomes keep their holds and never trigger an automatic retry.

The hypothesis chooses one explicit predicate: nonincreasing terminal strategy equity as costs increase, nondecreasing total fees, or strategy/benchmark terminal-equity equality across all three costs. These are falsifiable statements, not assumed financial laws or evidence of profitability. The engineer must preserve that choice. A derivative specification is registered before a new complete frozen D007 suite executes. Its exact parent assignment, fence, consumed intent, request and child submission are bound before financial work; an interruption retains inspectable lineage. The financial rule, dates and 0/10/25bps cases are unchanged. A cached old result cannot substitute for the new invocation.

Outbound context uses fixed method categories, approved failure codes, opaque aliases and safe prior-role projections. It excludes raw observations, dates, provider identifiers, numerical operands, predicate truth and earlier free-form model rationale. Visible model responses remain private; only validated projections pass onward. Local alias bindings document which retained artifacts support a handoff, not that the model saw their hidden contents. These are method-only reviews. Actual numerical acceptance requires separately executed local checks.

The method now uses the neutral code `frozen_next_open_three_cost_development_suite`. The exact `suite_integrity` category asserts only that the bound roster and current specification passed the existing local validator at packet preparation. The broker re-runs that validator before each packet and retains the exact private configuration/suite/policy/role observation. A live-fenced event binds the observation and packet hashes to the assignment and planned request ID before dispatch; the authorized transport subsequently records the provider-body digest under that same ID. This preserves the proof for malformed responses or interrupted dispatches, without adding private proof references to model context. Missing or stale verification refuses the next call. Neither this fact nor an `execute` decision certifies data accuracy, financial correctness or predicate truth, and stop/block choices remain available.

An explicit stop prevents later stages; a critic's block remains recorded while the other reviewers still run. Completion means the stage sequence ended, not that reviewers agreed or a strategy passed. Future summaries use not_reached when no review stage published and incomplete for a partial published roster; method_no_blockers requires all four review stages and explicit no-blocking decisions. An observed response whose handoff failed cannot clear review. Earlier stopped receipts retain their incorrect method_no_blockers labels with the correction documented in their independent audits. Every result retains `operational_acceptance=False` and `investment_validation=False`; inspect `review_outcome`, dispatch counts and actual-model evidence separately. A used run key refuses automatic replay. The entrypoint is a one-shot CLI: broker source/Python identities are checked between stages, but future long-lived processes need additional loaded-code/revision coherence.

## Role state

`quanto.research_workflow.ResearchWorkflow` uses one existing `Provenance` connection per worker. A trusted supervisor calls `create_run(manifest)` with exact code/specification digests, explicitly admitted sanitized development inputs, and frozen per-role contracts. The seven ordered roles are director, hypothesis, engineer, data critic, statistical critic, quality and scope. The last two are separate oversight stages, not replacements for the research critics.

`issue_stage(run_id, role)` returns a random private capability once. Store it in the supervisor's private memory, never in a prompt, status card, worker name, artifact or log. Only its digest is persisted by this library. Losing a token requires explicit cancellation and a new run lineage; token recovery is not implemented.

`claim_stage` returns the issued identity and current fence. `authorize_intent` registers one allowed action and its exact input references. `start_intent` consumes the effect entitlement immediately before a trusted broker performs the action. `finish_intent` records verified result references; `finish_handoff` publishes the complete result set and exact reviewed inputs atomically with its terminal state. These APIs do not perform the effect themselves. A caller cannot turn a state receipt into evidence that a model or calculation ran.

Every effect entitlement and publication checks actor, lease, fence, cancellation and deadline in its transaction. A crash after an effect starts remains uncertain; there is no automatic retry or built-in reconciliation. `recover_expired` handles state, and `cancel_run` stops subsequent effects. The supervisor must distinguish state recovery from recovery of an external provider call. `ResearchDispatcher` binds role bounds, purpose allowance and shared budget authorization to the consumed intent on the same SQLite connection. It checks the current lease/accounting day after local reads immediately before sending. Direct state-library calls alone do not reserve money.

The supervisor is the trust boundary for admission and output sanitization. JSON validity, exact hashes, fixed actions and credential screening do not establish data rights or detect every private value. The same filesystem owner can bypass these cooperative controls. `complete` from `read_status` means every local stage published a complete handoff; it does not mean the full private operation or investment validation is complete.

## Failure memory

`quanto.failure_memory.FailureMemory` reads existing provenance submissions and experiment attempts. A strict query can filter source, status, kind/code, exact IDs/request hashes, bounded metadata keywords, latest disposition and result limit. It returns fixed metadata and a durable receipt containing the query and returned IDs. It does not read or index free-form diagnostic text as searchable content.

Kind, code and artifact-reference allowlists govern projection. The broker separately authorizes exact failure IDs and sends only approved categories with opaque failure aliases; local hashes and identifiers are not transmitted. Direct library callers still need their own access boundary. This is a private local retrieval service, not an authentication service. All retrieval/repair attempts that fit the bounded request envelope are retained, including semantic refusals. Memory's own submissions are excluded from subsequent searches.

Search is deliberately bounded: at most500 candidate rows per source,50 results,8 artifact references per result and32 total artifact verifications per query. `truncated` discloses scan/result limits; `artifact_state` separately discloses unavailable or unverified references. A no-match response is not proof that no older failure exists. Query an exact known ID to retrieve a record outside the recent candidate scan.

`append_disposition` records an append-only correction or reopening claim linked to the original failure. A correction requires a retained, allowlisted fix artifact; it does not prove the fix works. Original outcomes remain unchanged, and later artifact loss stays visible. Independent review must assess the correction's substance.

The broker's failure context has exactly nine fields: alias, code, status, disposition, disposition_recorded, provisional, artifact_state, disposition_artifact_state and relation. A missing claim remains unresolved with disposition_recorded=false; it is not evidence that a historical refusal still applies. Evidence availability does not establish the truth of a correction claim. Every projected claim remains provisional.

The only positive relation is prior_refusal_in_bound_revision: the exact authorized submission, request identity and invalid outcome belong to the fully revalidated revision bound through the current suite and admission. It does not mean corrected, superseded, harmless or cleared. A verified nonmember receives no_relation_established. Missing or corrupt current dependencies refuse preparation instead of producing a negative relation. Original outcomes and disposition records remain unchanged.

The hypothesis effect retrieves one private registered basis. Its query receipts must begin and finish inside that basis's registration interval, which must itself follow the current assignment's started query effect. A basis cannot be reused by another run. Later packet preparations revisit only those exact records, without another memory search. They verify the latest disposition identity, original outcomes, evidence availability and current suite dependencies; any relevant change refuses the packet rather than silently refreshing context.

Each fresh observation must follow the current assignment and can bind only once. The broker revalidates it inside the live lease transaction and binds the exact packet, configuration, role, fence and planned request ID before dispatch. Revalidation performs no schema initialization, implicit commit or new query. Private basis/observation references never become model input aliases. These controls cover cooperating application execution; they do not attest against a privileged local owner.

## Acceptance boundary

The qualified failure-context increment separately passed1256 tests plus12 subtests in source and clean noneditable installation, with independent exact-lineage, current-state, one-use binding, transaction rollback, complete-egress and stop/block probes. Independent criticism reproduced and closed cross-run basis reuse and a fresh basis wrapping old query receipts. The [contract](reviews/D008-applicability-contract.md), [criticism](reviews/D008-applicability-critic.md) and [quality](reviews/D008-applicability-quality.md) reports retain exact identities and failed intermediate verification attempts. These are synthetic software checks. A later third actual workflow reached six publications/seven responses but failed scope output parsing; its retained financial work awaits independent numerical acceptance.

Independent criticism closed two transport timing/accounting defects and a parent-child crash-lineage gap. Separate quality passed1087 tests plus12 subtests in both source and clean noneditable installation, with independent full-workflow, arithmetic, privacy, cancellation and interruption probes. The later method-packet correction separately passed1133 tests plus12 subtests in both environments, with independent stale/missing-suite, privacy, stop/block and predispatch proof-recovery probes. All those software workflow observations use invented data and injected model responses. They establish software behavior, not actual-model competence, historical acceptance or investment performance.

The first actual attempt stopped at engineer after three Haiku responses. Separate trace/quality/scope checks confirmed no financial launch or later operational reviewers; numerical verification was not run. It exposed an inaccurate trailing-return method label for the unchanged SMA engine. The corrected neutral label and integrity-only method context are separate revised artifacts; the original trace remains unsuccessful and unchanged. A causal explanation for the model stop is not established by the label defect alone.

The next acceptance needs available budget, current historical admission, observed actual role outputs, a materially selected new registered calculation and independent criticism/quality/scope review of that exact trace. The model-only quality stage does not replace executed independent numerical validation. Persistent R14 operation, protected evaluation, research scheduling/restore, paper operation and live readiness remain incomplete. Application controls constrain cooperating processes; a privileged filesystem owner can bypass them.
