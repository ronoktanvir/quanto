## Required boundaries

**Creation ownership is observed rather than inferred.** The first child records the file descriptor returned by the original exclusive-create syscall. A competing valid creator is refused; its database remains byte-identical. A collision while recording the create witness leaves the new empty control file and failed attempt in place, with no accepted result. A consumed attempt cannot be retried under a different name.

**Reopen cannot silently adopt a replacement.** The module-local OS guard refuses a new create syscall during reopen. The SQLite guard changes ordinary connections to existing-only `mode=rw`, retains read-only connections and checks the expected identity before and after connection. An independently injected byte-identical replacement with a different inode was refused. A permissions change before reopen also refused. These are active controller restrictions; they are not evidence that the unwrapped product API or another process cannot create a store.

**The complete state is checked.** Source inspection confirms exact schema/index/trigger comparison, configuration/root binding, one default principal, one canonical bootstrap audit event and empty remaining tables. The independent positive probe queried SQLite directly and confirmed all 18 application tables: three bootstrap tables containing ten rows in total, and 15 empty tables. Both children use distinct observed process IDs, terminate, and agree on state and loaded-source identities. All limitation flags remain false.

**Failures after process launch retain ownership.** An independently injected collision in the owned-child receipt occurred after `Popen` returned. The parent killed and reaped that actual child, retained the colliding receipt, and produced failure evidence rather than success. A work-deadline expiry after successful bootstrap prevented the later reopen launch. The source shares one work deadline across both children and terminal publication; its failure/finally paths clean up the actual retained child handle. This does not guarantee cleanup after an uncatchable parent kill or an uninterruptible kernel operation; child deadlines and the later lead's outer-process observation remain separate safeguards.

**Evidence remains bound and local.** A source change between the parent's pin and child loading refused before control creation. A hardlinked child-result receipt was refused instead of adopted. Preexisting SQLite sidecars caused preflight refusal. Alternate SQLite targets and URI modes were rejected by the audit boundary. Loaded callable changes altered the recorded code identity. The exact registry bytes are compiled into a fresh module; controller-owned OS/SQLite substitutions are explicit in the reviewed source. The interpreter flags and empty requested child environment avoid project startup customization. This is a cooperating-process boundary, not hostile-owner isolation or a comprehensive monitor of arbitrary native code.

## Actual-use conditions

The lead must still verify the real process/entrypoint cut and source/controller review evidence. The controller's required preflight booleans and evidence list are a binding to that lead-owned observation, not an independent proof that workers are quiescent. A status file, archived PID or the presence of a valid-looking receipt cannot replace current ownership and liveness evidence.

An actual result requires a clean observed outer exit, no timeout or failure receipt, exact intent/phase/result/source bindings and verification of the retained control state. An interrupted run or lost outer result remains unaccepted even if a success-shaped file exists. Preserve partial stores and consumed attempts; do not delete, repair or automatically replay them.
