## Source facts that constrain rollout

- `cli.main` installs a session for its named acquisition, import, admission, suite, research and existing-submission routes. Underlying `Provenance` reads/publication and provider helpers still enforce authority, so invoking those functions directly does not inherit a CLI exemption.
- `Supervisor` creates `runtime/access-control/control.sqlite` only when absent. Existing empty/partial/wrong-root control files refuse rather than being initialized or repaired. Bootstrap records `legacy_unknown=True` when research.sqlite, the object directory or artifacts already exists. There is no supported operation to clear that marker. Both protected flags remain false and `protected_acquire` refuses.
- `serve` does not install a research-access session. Health, readiness, status and snapshot-status reads do not initialize its lazy conversation backend. Conversation/session routes can create/open conversations.sqlite and `Journal`; provider calls also use the research journal directly for budgets. Those paths are not a protected evaluator service.
- The website supervisor retains restart history and owns only children it actually launches. A healthy external server can remain running. Replacing disk source therefore does not prove that the existing supervisor/server loaded it. `/ready` checks status/assets, not loaded code identity.
- `operations --once` is not a read-only probe: it writes operations state. Normal supervision can request a paid incident diagnosis after failures. The service install command can stop/bootstrap the owned LaunchAgent. None belongs in an unqualified registry smoke check.

## Old services, failure and rollback

Only after that bounded result should a separate reviewed operation address actual loaded-service freshness where needed. Verify the exact owned LaunchAgent configuration and live ownership; a persisted PID alone is not authority. Preserve existing restart circuits, uncertainty, conversations and snapshot history. If an owned service is restarted, drain/reconcile any in-flight calls first and use the existing model-pause mechanism only with its prior state recorded and restored; it does not cancel already emitted requests. Never resume model calls merely because a maintenance timer expired. A healthy unknown port owner is not killed. New `/ready` and `/api/snapshot-status` observations establish website health/freshness only, not access-controller rollout or loaded-module identity.

On bootstrap failure, leave control/attempt evidence in place and keep the cut unaccepted. A partial file needs a reviewed repair disposition; removing it and rerunning would erase the failed boundary. Prefer a fix forward. Reverting source, reopening old code or restoring research.sqlite cannot reset the control store, release uncertain effects or justify protection. If a fallback development process cannot honor the new boundary, label it outside rollout and keep protected use disabled rather than claiming rollback preserved enforcement.

Administrative recovery/capture/inspection helpers, direct SQLite/file reads, operator-provided request/packet files, ignored scripts and already-held numerical arrays remain outside this first ordinary-route cut. The D009 capture predates the new control store. Before real evaluator use, complete the route inventory and legacy reconciliation, evaluator storage/service isolation, persistent principal policy, private source review, fixed release schedule, reviewed statistics/pilot selection, consistent multi-store restore and external freshness/effect barriers. Full persistent research operation, prospective paper work and separately authorized live execution remain the objective.
