## Source-confirmed preparation requirements

Its preliminary SQLite checks require regular files only. `Journal.__init__` opens the database and initializes schema; it also does not repair permissions. Neither constructor is a read-only permission probe.

`Provenance._read_identity` subsequently rejects any group/other permission bits on the research database, wrong owner, multiple hard links or changed inode. Therefore the lead-reported `0644` existing database will fail guarded object reads if unchanged. A content intent/effect and application submission can already have been recorded before this refusal. The source review did not independently observe the actual mode.

Check any existing sidecars separately and stop on unexpected identity/state. This is a local permission correction, not reconciliation, antirollback or global process isolation.
