# D008 independent perspective: persistent operations and reliability

## Recommendation

Build research orchestration as a durable, journal-backed workflow with explicit stage records and reconciliation, rather than extending the website supervisor into a general scheduler. The current journal is a sound primitive layer: reservations are atomic and shared by cooperating callers; dispatch authorization is single-use and must precede the send; ambiguous calls retain their full hold; jobs have idempotent IDs, bounded attempts, leases and monotonically increasing fences. The gap is the coordinator that binds these primitives to the five-role lifecycle, protected evaluation, failure retrieval and restart recovery. The LaunchAgent watches the dashboard only; it is not evidence of unattended research execution.

The smallest sound workflow is a parent run plus immutable stage attempts. A run freezes its plan, code/specification/data identities, evidence kind, role versions, model identities, access class, output schema and policy revision. Stages proceed through director plan, hypothesis proposal, deterministic experiment, two distinct research critiques, independent quality validation and independent scope review; protected evaluation and restricted release occur only when separately authorized. Each stage has a stable idempotency key from its run, stage, input hashes and role contract; each invocation has its own attempt identity. Store exact input/output hashes, requested and observed model, prompt revision, usage evidence, terminal reason and producer. A producer cannot satisfy its own reviewer stage.

## State and recovery boundaries

Use explicit stage states such as `pending`, `leased`, `dispatch_authorized`, `result_received`, `committed`, `failed`, `uncertain`, and `cancelled`. A worker may advance only with its current lease fence, and each transition plus its event should commit atomically. Persist the input and output artifact references before marking a stage committed. If a process dies after an external send but before recording the response, recovery must mark the call uncertain; the coordinator must not replay it automatically. A provider may have processed or billed a request even when the client saw a timeout. Reconcile from provider evidence where available; absent evidence, retain the conservative hold and require an operator decision or a new, separately budgeted attempt. Similar logic applies to protected evaluation: authorization or any protected read consumes the one registered evaluation, including crashes, failures and unpublished results. Exact deterministic replay is a verification attempt on that same entitlement, not a fresh test.

The existing lease primitive rejects stale completion, but a lease alone cannot cancel a running subprocess or external request. Cancellation should first append a durable request and revoke future dispatch; workers check it before each side effect. An already-authorized network request remains uncertain until reconciled. Resuming a run reclaims only stages known not to have crossed a side-effect boundary; stale leases receive new fences, and prior attempts remain visible. Do not automatically clear holds, reset an exhausted retry count, or convert pending submissions into failures at startup.

## Roles, tools and cost

The five persistent roles need versioned contracts and narrow capabilities: director selects predeclared work; hypothesis researcher proposes falsifiable rules; experiment engineer submits typed deterministic jobs; data/implementation critic inspects mechanics; statistical/portfolio critic inspects inference and selection. They should not receive arbitrary paths or direct journal writes. Workers submit typed requests; deterministic tools execute bounded operations. Research credentials exclude broker credentials, and no research role places orders. Quality and scope reviewers remain separate gates.

Before external dispatch, atomically reserve the conservative maximum against the daily shared project budget, persist purpose and role, then authorize once immediately before sending. The ledger binds accounting day to authorization in America/Los_Angeles, blocks duplicate dispatch IDs and refuses old-day reservations. It governs cooperating Quanto clients only. A low or unavailable balance—reported near $2.02 at this review, a time-bound observation—must defer paid work while deterministic stages continue. Never shrink a required review, switch models, reset holds at midnight or retry without a new reservation. Signed-in Claude Code council calls are a separate cost problem: CLI estimates are not invoices and one generation can exceed them. The API ledger is not a hard cap for that route; preserve observed model identity and outcome, and defer unsafe calls.

Set bounds before dispatch: prompt and output sizes, wall time, concurrency, tool calls, retries, stage time and run time. Malformed, truncated or wrong-model output fails the stage. A paid retry is a new attempt with a unique reservation; no model fallback. Persist fixed error categories and hashes, not raw provider bodies or secrets. Model output cannot expand capabilities, approve protected access, change evaluation windows or promote execution.

## Protected evaluation and failure memory

Protected prices and derived outputs need an evaluator-owned storage and capability boundary, not just an `evaluation` role label or a wrapper around the explorer. Ordinary role workers receive no paths or object references to protected bytes. An evaluation reservation binds security aliases, source/feed/adjustment, full acquisition envelope, warmup and final sessions, code/specification, cost cases, authorized actors and a frozen public receipt schema. Record access before each request. Release only allowlisted fixed states and integrity codes; anomaly dates, returns, trades, missing-session locations and outcome-derived diagnostics remain protected unless an independently reviewed policy explicitly permits them. In the present same-user process model, role capabilities are cooperative controls, not protection from the owner or arbitrary local scripts; a stronger boundary needs a separate OS identity/service whose storage and credentials research processes cannot read.

Failure memory should be queryable by fixed category, component, stage, code/data/specification identity and artifact hash, with exact attempt chronology and links to the repair that followed. Preserve failures, invalid submissions, rejected proposals and uncertain calls as first-class records; do not overwrite a failure with later success. Keep sensitive diagnostic artifacts private and send only sanitized packets to external reviewers. A search result is context, not permission to reuse exposed data or to retry a side effect.

## Restore and acceptance

Before unattended research, define backup scope for the SQLite journal, content-addressed objects, protected evaluator store, workflow configuration and trusted event-chain head. Back up a consistent snapshot, record its identities outside the machine, then test restoration into an isolated location. Startup verifies schema, object hashes, journal chain against the trusted checkpoint, lease age and all uncertain dispatch/evaluation states before scheduling new work. Corruption or a missing checkpoint fails closed; restore must not replay paid calls or reset the daily budget. SQLite triggers and a hash chain provide tamper evidence, not immutability, and a local copy alone cannot detect whole-chain rewrite or suffix truncation.

Acceptance should use fault injection and synthetic fixtures: concurrent job/budget claims; process death at every transition; stale completion; cancellation before and after dispatch; timeout after provider receipt; duplicate enqueue; malformed/truncated output; unavailable budget with local work continuing; wrong model; protected-reference leakage through logs, dashboard or review packet; evaluation crash after first read; and restore with altered artifacts or chain head. Verify single dispatch authorization, no paid auto-retry, no stale-fence write, no fresh evaluation entitlement after exposure, and truthful pending/failed/uncertain states. This tests workflow behavior, not market merit or unattended uptime.
