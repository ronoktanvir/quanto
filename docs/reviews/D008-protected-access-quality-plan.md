**This is an unexecuted test plan, not implementation acceptance.** The decisive test is whether an ordinary request is denied before its first content open or transport call, with durable authority/consumption evidence that survives a research-transaction rollback and process restart. ## Contract being tested

Ordinary services receive an explicitly installed supervisor session binding a canonical development root, private control-store identity, persistent principal and relation revision. Classification precedes access. Issuing an intent immediately blocks conflicting reservation preparation; an exact one-use effect start commits before I/O. After a start, missing or failed completion preserves access/uncertainty. Only a durable no-start rejection supported by the access log can be treated as rejected without access.

The lead relayed these builder dispositions while implementation was in progress; they are commitments to verify, not observations of code behavior:

- Every actual content open needs a fresh intent/start; an idempotent outcome lookup must not reopen the file. Reusing one issued effect refuses.
- Page permits derive the exact GET URL and full page token from the frozen normalized request. `_dispatch` consumes the start; `_http` requires a live consumed grant. Synthetic sessions prohibit real network transport.
- Control commits survive research-database transaction rollback only. No copied-control-database or external antirollback guarantee is claimed.
- An acquisition denial must precede ordinary request registration/publication. A denied valid query uses a constant ordinary request marker and fixed reason, with no artifact, symbol/date or control reference. Invalid/unclassifiable requests need the same independent egress assessment.

The contract does not activate evaluator acquisition or make any reservation eligible for protected performance use. Same-user administrative constructors, raw filesystem access, old processes and deliberately selected independent workspaces remain outside a hostile-owner isolation claim. Unknown legacy history and unresolved identity/coverage cannot establish an untouched interval.

## Independent harness and evidence method

The prepared harness imports no Quanto implementation. It contains transport/content-open spies, a real-thread pause point, synthetic-path validation, a sample marker-egress assertion and a conceptual adapter protocol. The adapter will be bound to exact frozen supervisor APIs only after source/test hashes are supplied. Its syntax was parsed; no test or candidate was run.

Future tests will use invented temporary roots, fake credentials/responses and real SQLite control/research stores. Refused routes must show both zero physical target opens/fake transport calls and the expected bounded private control transition. A positive fake I/O callback will open a separate read-only control connection, without an initializing constructor, and assert that the exact effect start is already committed. Transport entry and attempted content-open counters are recorded before sentinel assertions, so an API that catches a test exception cannot masquerade as zero attempted I/O. Mocking the authorization decision itself would hide the property being tested and is not the planned method.

File spies must cover actual target opens through both descriptor-relative `os.open` and any supported high-level open path. Directory/source/configuration metadata opens are distinguished from protected content; a global count of all file descriptors is not an exposure measurement. Transport spies cover injected dispatch and the mocked raw HTTP connection. A process-wide external-network refusal remains installed throughout execution. Each worker gets an explicitly issued synthetic session; no actual `.env`, provider credential or project root is used.

Use events/barriers rather than sleeps to choose race order. Inject faults at commit/I/O/publication boundaries, not by replacing the transaction/conflict predicate with a fake answer. Crash tests use child processes against owned temporary stores, then reopen control state independently. They demonstrate process-restart persistence, not power-loss durability, filesystem-owner resistance or an external freshness witness.

Outcome lookup may be idempotent; performing the effect again is not. An effect with no physical I/O after a crash still remains consumed by policy. Conversely, positive fixtures are necessary so a blanket deny implementation cannot pass the boundary tests merely by refusing everything.

## Egress and denied-publication cases

The baseline acquisition functions store prepared URLs/requests before transport and retain normalized requests in failure receipts. Therefore zero transport calls alone is insufficient: a denied request can still disclose private control/query details through ordinary publication. The builder is correcting that draft path; tests must verify the correction at every return/catch path.

Sample canaries supplement exact schema assertions; they do not establish universal information-flow safety. Allowed development acquisition can still publish its legitimate development evidence. The fixed-denial requirement does not turn every ordinary symbol/date into forbidden output, and does not authorize any protected lifecycle disclosure.
