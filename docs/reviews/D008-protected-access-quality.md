- A separate read-only SQLite connection sees a committed content-effect start before the physical object open; reuse of already verified bytes adds no physical open or effect.
- Unknown reads under a reservation and direct `_blob` calls without a grant refuse before opening content.
- An alias merge that creates a conflict prevents cached bytes from being returned; tombstones and principal revocation also fence reuse.
- A failure while committing the effect-start audit prevents fake transport. The issued intent still blocks a conflicting reservation.
- A real child-process exit after committed effect-start leaves an effect without terminal outcome. Reopening the supervisor preserves the conflict. This is process-crash persistence, not power-loss or external antirollback evidence.

## Required work before acceptance

The separate critic reported four defects on this same frozen candidate: generic writes can leave no access evidence before later reservation; foreign-security corporate-action records can retain overly narrow classification; a disjoint bars acquisition can fail final receipt access because the receipt remains unclassified; and ordinary `AccessIntent.bind_object` can classify arbitrary retained bytes from a caller-chosen request without a corresponding acquisition effect. These are critic-attributed reproductions, not tests executed by this reviewer. They prevent quality acceptance despite the passing cases above.

Corrections need new exact source identities and independent regression checks across both positive and denial paths. The eventual full compatibility run also needs explicit, narrowly scoped D009 fixture adaptation. The earlier 1,089-test producer run predates final hardening and is not evidence for this frozen candidate. No full CI-timeout change is justified from this bounded selection.

Legacy reconciliation, global deployment binding, old loaded processes, administrative readers, evaluator isolation/release, multi-store recovery and external freshness remain incomplete. The local control database protects against ordinary research-transaction rollback; it is not an externally anchored newest-state witness. No R13/R14, statistical acceptance, sustained operation or live authority is certified here.
