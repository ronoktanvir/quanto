## Required contract clarifications

**Successful admission does not promise stored original admission-request bytes.** Both pinned `admit_dataset` implementations pass a frozen string to `begin`, then store the result containing its parsed `request`; they do not publish the original admission-request string. `Provenance.begin` records digest, length and encoding, not content. The proposal's successful-admission row nevertheless says to bind the artifact to the registered request identity. Define this precisely: validate the outcome/artifact and event bindings, preserve the embedded parsed request, and verify its relationship to original bytes only when an explicit retained object matches the submission digest/length/encoding. If those unpromised bytes are absent, retain a named original-request-availability/binding gap. Do not hash canonicalized `result.request` as a substitute or refuse the entire historical success merely because the writer never promised that object. Two whitespace-different valid JSON strings can have the same parsed request and different submission digests. The acquisition originals referenced by `submitted_requests`, and prior refusal originals explicitly referenced by policy lineage, remain separate required dependencies.

**Select a policy-revision artifact through its own recorded producer identity.** The proposal explicitly specifies an admission/explorer pair for admission, but should state the policy selector independently. A policy artifact needs the recorded `policy_revision.py` source identity `eb7ac89bbf1c85cf276f614bd296ad82f2d22f94d723788a3718c42ff5b12625` and the supported D007 explorer identity emitter, followed by exact policy rules/shape and registration bindings. D007 rule text or a known admission/explorer pair alone cannot establish that producer. Preserve all other recorded source identities as external requirements; unknown/missing policy identity remains unresolved, while a known selected producer with contradictory rules/shape refuses. The D007 emitter explicitly includes `policy_revision.py`; no new authority mechanism is needed.
