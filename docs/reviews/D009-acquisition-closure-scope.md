## Source-grounded scope

The pinned acquisition writers publish versionless prepared requests while their receipts and normalized observations have versioned contracts. Role/profile-specific version validation is therefore justified. Removing a global version check is insufficient by itself: every existing versioned role must retain its current version/type/refusal requirements. Known historical producer pairs select finite shapes; absent identity or resemblance to an older shape must never select a verified historical profile.

The public source supports the plan's distinction between original submitted bytes and prepared normalized requests. Bars/calendar do not automatically preserve their original input bytes, whereas actions retain them. Admission and policy consumers explicitly bind required original bytes to submission digest and length. Neither reconstruction nor canonicalization may substitute for those original bytes. The source also confirms that `validate_revision` adds a self-reference to its returned object, so comparing the augmented embedded value with the unaugmented stored artifact requires the proposed explicit distinction.

The proposed traversal covers failure history as well as successful products: pending preparation/page events, partial acquisition receipts, invalid admissions, earlier plans and policy predecessors remain roots or typed references. Raw provider/source content stays opaque. Manual facts, reviews, schedules and plans derive a finite **consumer contract**, not an authenticated producer identity; arbitrary additional fields must remain an unresolved coverage gap. These boundaries preserve useful structural evidence without manufacturing historical validity.

## Required implementation clarifications

1. **Permit a root plan without a predecessor.** The proposal's sentence that predecessor plans use “exactly one” link name is too broad if applied to every plan. Pinned `policy_revision._plans` accepts no link for the first/root plan. Each subsequent plan must have exactly one of `previous_plan_bytes_sha256` or `previous_plan_sha256`, equal to the preceding retained plan; both fields or a disconnected chain refuse. Preserve the separate post-acquisition additive-refinement and event-order checks.
2. **Retain failures that lack origin metadata.** Both acquisition writers can fail before recording a normalizer digest. Such records cannot select a verified producer merely from submission kind, receipt fields or another run's identity. Keep their unambiguous required references and an explicit unresolved-origin gap. A supported complete acquisition must satisfy its stronger bindings; pending or interrupted publication must not gain an invented receipt, normalized object or finish event.
3. **Separate recorded pagination from verified pagination.** Pure URL/query, count, byte-length and event/receipt equality checks can verify structural consistency. With raw bodies opaque, they cannot establish that each token came from the preceding response, that no provider page was omitted, or that normalized rows equal raw observations. Preserve those limits explicitly under the existing normalization-not-replayed gap or equally precise gaps. A retained `pagination_complete:true` is a recorded claim within this increment, not independently replayed provider completeness.
4. **Do not erase gaps through shared roles.** Unknown manual fields, missing origin and unavailable external source/environment evidence remain gaps even when known nested references are traversed or the same bytes also have a supported incoming role. Preserve every incoming interpretation and reject contradictory known contracts. Remove a generic gap only when its complete reference-bearing subset has an explicit finite replacement; replacing it with a narrower named gap does not complete the parent artifact.

These clarifications apply the documented contracts and do not introduce a new architecture. Separate criticism should assess the exact field inventory and implementation mechanics. Invented fixtures need root-plan/no-link and later-link alternatives, pre-normalizer failures, pending page events, strict version isolation, known-current field deletion, original/prepared request confusion, manual extensions and explicit non-replay limits, alongside the proposal's existing corruption, ordering, multi-role and bounds cases.
