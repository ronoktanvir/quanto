## C2: URL parsing erases forbidden literal characters

Priority: required strict-profile correction. `Lineage.url` at line385 calls `urlsplit` immediately after the nonempty-length check. Python removes literal tab/newline characters during parsing. Appending either a tab or newline to an otherwise valid stored prepared URL is therefore accepted, and its `acquisition_request` node receives `supported_structure_checked`.

The selected historical acquisition writer generates URLs through its fixed encoder; its `_route` also rejects any literal whitespace before parsing. Preserve the stored bytes, but reject literal whitespace/control characters before semantic URL comparison. Keep duplicate-parameter, endpoint, token and request-equality checks unchanged. Include prepared and page URL fixtures because both use this shared parser.
