## Required selector correction

The initial proposal abbreviates two event names as `broker_packet_bound` and `broker_failure_basis_bound`. Those are arguments passed to `ResearchWorkflow._event`; the method prefixes them with `workflow_`. The captured event selectors must therefore use **`workflow_broker_packet_bound` and `workflow_broker_failure_basis_bound`**, as the broker's own SQL queries already do. I independently confirmed that distinction in the public source. Matching only the bare names would miss pre-dispatch evidence from interrupted work and falsely narrow the root inventory.

This correction is a concrete implementation condition within the accepted plan, not a policy change. Include both selectors in synthetic root-extraction tests, including packet/basis publication without a terminal stage and the optional director-basis case. Preserve the actual field/role meanings rather than guessing from digest-like spelling.

Chats/sessions remain excluded while all shared research-ledger costs, uncertainty, dispatch consumption, exposure and failures remain preserved.
