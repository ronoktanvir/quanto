## The claim and the boundary

The current candidate preserves the entire captured research database and every available canonical non-tombstoned object. Its known database-reference checks do not establish recursive evidence closure. Closure means that a supported producer/consumer contract identifies every required dependency and each dependency is present and intact, or its unavailability is explicitly recorded. It does not mean that the original economic conclusions are correct, that today's rules accept yesterday's study, or that historical code can be executed safely.

Use separate claims for database/object preservation, supported structural-reference coverage, required source/audit availability, historical reproducibility, and external recovery. A digest-only request can be faithfully preserved according to its original recording contract even when the original request bytes were never saved. That does not make the original request reproducible. Conversely, a consumer that explicitly reads source/report bytes establishes a real file dependency; saving its digest alone cannot satisfy that dependency. An essential tombstoned file remains an explicit evidence limitation and must never be resurrected.

The accepted D009 policy permits research-only recovery with chat continuity excluded. It does not permit silently excluding the source or audit evidence needed to support retained research claims. The proposed first dependency report therefore keeps `typed_closure_complete=False`, `full_recovery_accepted=False`, `historical_replay_verified=False` and `execution_enabled=False`. No change to the existing snapshot flags, manifest or frozen capture code is proposed.

## Root selection and edge types

Classify records by their database origin and declared document role before looking at their payload. A `kind`/`schema_version` pair is a consistency check within an authorized profile, not authority to interpret arbitrary copied bytes. Provider JSON, source HTML/PDF and raw model text can contain invented kinds or digest-looking values; they remain opaque leaves when reached through those roles. Versionless configuration, stage, request, handoff and receipt objects require explicit profiles keyed to the producer and incoming edge. An orphan remains unclassified inventory unless a recorded origin establishes its role. Multiple roles for the same digest must be retained; conflicting structural roles cause an unsupported/invalid result rather than selecting the convenient interpretation.

Each extracted edge should contain the parent identity, exact field location, origin/profile version, edge type, expected child role and observed availability. Use these distinctions:

| Edge type | Treatment and reason |
| --- | --- |
| Required content object | Verify the exact digest against the snapshot inventory and tombstone table. Missing live bytes fail the supported closure check; tombstoned bytes remain omitted and prevent the relevant complete-evidence claim. |
| Inline identity | Hash the actual retained inline value when its canonical encoding is specified; never require a separate object merely because the field ends in `_sha256`. If the value was never retained, report that limited identity evidence. |
| Historical availability observation | Preserve the saved available/unavailable state and its temporal context. Do not rewrite it using today's presence or turn every key in an availability map into a mandatory file. Independently declared required edges still apply. |
| Database/event identity | Resolve submission, run, request, attempt, assignment and event bindings against the captured database. IDs and event numbers are not filesystem paths. Structural binding is distinct from re-executing the state transition. |
| Required external evidence | Record a bounded requirement for exact source/audit bytes. Resolve only through a separately approved evidence catalog, never by following a stored arbitrary path or fetching a URL. Until resolved, coverage is incomplete. |

Retain all existing database roots in `recovery.py`, including failed outcomes, workflow input/effect/handoff references, broker configuration/aliases/stages/tool requests, private-response objects, comparison registrations, failure fixes and pending acquisition events. Add the following explicitly missing origin cases to the dependency registry rather than assuming terminal `artifact_refs` lists cover them:

- `broker_packet_bound`: configuration, packet, verification and failure-context digests plus optional failure-basis digest. `_bind_model_packet` records these before dispatch; a failed stage may never publish a stage record.
- `broker_failure_basis_bound`: configuration and basis digests, with the corresponding workflow/effect binding. A later failure must not hide a completed retrieval.
- Ledger `outcomes.result`: the `explorer.run_submission` object-store result shape and the legacy `cli.run_demo` external synthetic-file shape are different profiles.
- Ledger `reviews`: `artifact_hash` identifies the reviewed packet in `critic.request_review`; `findings.report_sha256` identifies the external report. They are not two unconditional object-store references.
- Provenance kind/status-specific details and recorded requests: a submission digest alone does not promise saved bytes. Unknown kinds or unrecognized reference-bearing shapes are explicit unsupported coverage, including failed/pending records. A reviewed registry must also identify known non-reference-bearing event shapes; unknown event kinds cannot silently receive universal coverage.

`study_suite_launches.request_sha256`, suite members' request digests, workflow `code_sha256`/`specification_sha256`, prompt hashes, dispatch body hashes and function/global identity hashes are not blanket content roots. In particular, a dispatch packet hash and the packet object referenced by a broker binding have different contracts despite similar field names.

## Reuse without replay or current-code substitution

Reuse the frozen snapshot inspector for manifest/file/database/event verification, and reuse pure canonical JSON/hash and bounded structural checks where their interface has no source or state effects. Introduce an explicit snapshot reader with read-only queries and digest-addressed reads limited to manifest-listed objects. No object lookup accepts a filesystem path. Bound documents, recursion/worklist size, total edges, rows, bytes and elapsed time; detect duplicate JSON keys, invalid digests, cycles and ambiguous profiles. Keep the snapshot self-contained and inert, with the same no-link/no-special-file restrictions and read-only SQLite authorizer. Recheck byte identities across inspection so concurrent modification cannot produce an accepted mixed report.

Use existing validators as specification references, not as a convenience API for this task. `Journal`/`Provenance`/workflow constructors write schema; suite `inspect_run` constructs a store; admission/suite/comparison checks call current policy; explorer and failure-context identities read current source; publication, acquisition and financial execution functions create observations or perform work. Adapting a mutable class with `object.__new__` does not establish a safe read-only contract. Historical structural readers should be small pure extractors and checks over captured bytes/rows, independently tested. They must not import an arbitrary module named by a saved artifact or execute saved code.

Known inline comparisons and event ordering can be checked without financial replay. They establish recorded bindings, not the correctness of the old computation. A current code mismatch should be an unavailable/mismatched historical-source requirement, not a reason to rewrite the saved artifact or run the current engine to obtain replacement evidence.
