## Origin-classification concern awaiting independent disposition

Source inspection suggests a remaining mismatch with the origin-first contract. `_Reader.roots` treats an `artifact_sha256` key in an arbitrary non-explorer outcome as external evidence, and a `report_sha256` key in arbitrary review findings as an external report digest. However, `Journal.finish_attempt` and `record_review` permit any bounded canonical JSON for those respective payloads. A valid generic dictionary may use those names for ordinary text or non-digest values; a digest-looking value still does not establish the corresponding producer contract.

Consequently, a generic result such as `{"artifact_sha256":"ordinary note"}` or findings such as `{"report_sha256":7}` appears to raise `invalid_reference` instead of recording unsupported semantics. The mandatory `reviews.artifact_hash` column is different: its ledger method explicitly enforces a SHA-256 identity, so that column is not the objection. The issue concerns inferring additional typed edges from payload spelling without an established origin. I sent this source hypothesis to the independent critic for reproduction; no test result is claimed by scope.

A fix should select the known explorer/legacy or external-review producer contract before extracting its typed fields, or retain unsupported generic payload semantics without inventing edges. It must continue to reject malformed data in an established supported profile. This is a routine classifier correction, not a reason to widen the implementation or add an approval process.
