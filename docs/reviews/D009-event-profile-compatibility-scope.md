## Evidence supports compatibility work, not inferred origin

The public-history review identifies two packet writer generations. Broker revisions 038714 and eb47 emit configuration, packet and verification references, with neither failure field. Revision 9ed additionally emits failure-context and failure-basis fields and introduces the separate failure-basis event. All documented packet generations require verification; the older 6d source emits no packet-binding event and cannot justify a weaker two-reference profile. The current public broker and workflow bytes match the plan's 9ed broker and common workflow identities, including the stored `workflow_` prefix.

The frozen closure registry currently requires all five packet fields for every recognized packet event. That is inconsistent with the documented earlier writer representation. The safe survey reports ten selected events: two packet shapes compatible with the earlier format, seven compatible with the current format, and one compatible with the current failure-basis format. All nine packet shapes contain the three base digest fields; the current-compatible packet subset contains six digest-valued basis fields and one explicit null. The aggregates are internally coherent and identify a useful compatibility case.

These are shape observations, not established producer origin or role semantics. The survey explicitly keeps `producer_origin_verified`, `historical_profile_validity_established` and `nullable_basis_role_semantics_checked` false. It ran neither the full inspector nor roots/graph traversal. The lead reports the separate clean survey execution; I reviewed its allowed result, not its underlying private launch/receipt evidence. A current event damaged by removal of both failure fields can resemble the older shape, so the observed shape counts cannot choose a trusted profile.

## Required selector and refusal contract

The chosen strongest selector should bind the event's parent and configuration reference to the same `research_broker_runs` row, read only the digest-checked configuration object from the pinned inventory, and require the canonical recorded `code_identity` hash to equal that row's `code_sha256`. Select only an explicitly reviewed broker/workflow source-digest pair. Configuration, row and event disagreement must not be converted into legacy compatibility. A missing or tombstoned origin document cannot be reconstructed from today's source, timestamps, event order or the apparent shape; preserve refusal or an explicit unresolved/tombstoned gap without certifying the profile.

The allowlist is finite evidence about recorded writer contracts. It does not execute historical code, fetch missing source or certify the entire configuration, broker run, role assignment or workflow. Existing code-identity and same-user threat limitations remain: these are mutually bound application records under a cooperating-process assumption, not independent proof that an unmodified historical executable produced them.

Once a producer profile is selected, require that profile's documented reference fields and types:

- Known legacy packet profiles require all three base references, including verification, and retain an explicit gap for modern failure-context/basis semantics that those writers did not record. Do not manufacture those objects or infer them from later stages.
- A known current packet must retain both failure fields even when its basis is explicitly null. Dropping one or both fields must refuse; a changed shape cannot downgrade a known current origin. Keep mandatory digests non-null and apply only the documented nullable-basis condition. A syntactically present null alone does not prove the event's role or assignment is valid; any unverified role/assignment relation remains an explicit semantic gap.
- The separate failure-basis event retains configuration/basis references under its documented current writer. An impossible event/profile combination cannot be accepted by borrowing the format from another writer. Unknown producer/workflow pairs remain unsupported or unresolved, never verified legacy/current merely because their keys match.

Invented extra SHA-like keys must not become dependency authority. Preserve required-object/tombstone checks, the exact stored event selectors, pending-event roots and the distinction between a structural reference check and complete event semantics. The origin selector may expand the finite structural checks needed to resolve this compatibility defect; it must not silently claim full historical broker validation.
