## Bounded execution and truthful outcomes

Each selected step receives a finite timeout greater than zero and no longer than 360 seconds. The execution deadline begins immediately before process creation, and the parent checks both monotonic and wall-clock deadlines, including before releasing the child's launch gate. Private stdout and stderr have explicit 256-KiB and 64-KiB bounds. The parent attempts to kill and reap its owned process group on expiry, interruption, excessive output or surviving descendants. Preflight and post-run local file verification are outside the child execution interval; this is not a claim that all filesystem operations have a total wall-clock bound.

`CLEANUP_SECONDS=5` bounds each reap wait. Exceptional paths can call the cleanup routine twice, so there is no absolute five-second total cleanup guarantee. I raised the introductory wording, and the final documentation-only correction now states this limitation along with the unpreempted local I/O. Failure to observe or kill the group remains uncertainty. This qualification does not change the command or authority scope; independent quality determines the behavior of the concrete failure cases.

The attempt directory is claimed exclusively, the child's start record is exclusive, and neither an existing directory nor a partial attempt is automatically resumed. A new path is not authorization to retry a consumed effect: actual operational selection must preserve the prior attempt and reconcile uncertainty. The fixed launch gate prevents a child from proceeding through authority/CLI work without the corresponding parent release, while lost spawn ownership or cleanup failure remains explicitly uncertain.

The receipt preserves exit code, reason, cleanup evidence, identity checks and private-output digests. `status=completed` means an observed process terminal under those controls; it does not mean the CLI succeeded or a financial result was accepted. The top-level command returns success only when the process receipt is completed and its exit code is zero.
